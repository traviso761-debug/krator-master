# Brief A: "Reed's Local" (a new Reed Lake tavern) and the Reed Lake interiors set

Read `settlements/mungo/briefs/00-common.md` first.

## Why
Mungo's offshore district is a floating reed village built from the Reed Lake kit (`settlements/reedlake/`), twice the
size of the kit's own composite village. The owner asked for **one new, large tavern in the Reed style, labelled
"Reed's Local"**, and said: "if inventing a new [building], put it in its culture's kit after building it rather than
making a whole new kit for this settlement", and "make sure all buildings socket in to existing interior and
furniture systems; build out interiors and furniture if needed and place in the appropriate sheet for their culture.
I'm not sure if Reed culture has interiors yet so you may need to start a sheet for them." Reed culture has NO interiors
set yet: you start it.

## Part 1: the tavern, in the Reed Lake kit
- Read `settlements/reedlake/README.md`, `DESIGN.md`, `API.md`, `NOTES.md`, `KNOWN_ISSUES.md`, `INDEX.md`, then the
  helpers you need in `src/75-rl-helpers.js` and two builders as models (`src/77-rl-village.js` has the great mudhif
  `rl_longhouse`; `src/78-rl-work.js` has the dock, weaver, warehouse).
- New fragment `settlements/reedlake/src/81-rl-tavern.js` (own seed block: **25600-25649**, `reseed(25601+(o.v|0))` at
  the top of the builder; the build checks seeds and top-level names). One def:
  `RL.def({key:'rl_tavern', name:"Reed's Local", family:'Hospitality', tags:{type:['tavern/inn'], wealth:'middle', lit:false, landmark:true}, w, d, h, build})`.
  Put a new family `Hospitality` on the kit sheet (check how families become rows in `90-rl-scene.js` / the target's
  `89z-rows.js`; edit `targets/reedlake/89z-rows.js` if the families are listed there).
- What it is: the lake people's big drinking hall, LARGE (bigger than the great mudhif's floor: think 26-34 m long),
  built entirely in the culture's vocabulary (`DESIGN.md`): a great reed-bundle arch hall (mudhif ribs, lattice front)
  or a pair of joined mudhifs, with a covered mat-decked veranda/landing over the water on the +z front where boats tie
  up (use `hnRLMoor` / `hnRLBoat`), a cook-fire on a mud slab, braziers and fire-cages for night (fire only, never
  electric: `lit:false`), hung woven cloths and pennants, gourd and jar stores, and a **sign** that reads
  **REED'S LOCAL**: a woven or painted board hung at the landing (a canvas texture with the lettering in the Andean
  palette `RAND`; keep the texture's colours in the map, not the tint). Name in the registry must be exactly
  `Reed's Local` (the inspector shows it).
- Furniture: the kit currently draws its own props (benches, jars) as kit items. The repo rule (README, SKILL 5d) is
  that furniture is catalog data. For the tavern, keep the builder to STRUCTURE (floor, ribs, walls, roof, landing,
  sign, fire slabs) and let the interiors set (Part 2) furnish the inside. Outdoor dressing on the landing may stay as
  kit items, as the other reed builders do.
- Placement contract the planner (Mungo) relies on: Mungo calls `VERN.place(scene,'rl_tavern',x,z,ry,{pad:false,v:0})`
  on a reed island it builds itself, whose top is y = 0 (the lake is `RL.WATER`, -0.45). So:
  * with `o.pad===false` the builder must not build its own pad; standing alone (`o.pad` unset) it builds one with
    `hnRLPad`, like the others;
  * everything that needs dry island stays inside `w x d`; the landing/veranda may reach out over water past the +z
    edge only if you say so in the def (`landing: <metres>` field) and in your report;
  * the door(s) on +z; report the door positions in the local frame (Mungo's people will walk in there).
- Budget: <= 60k triangles (`91a-rl-budget.js` classes; put it in the class that fits).
- Build `cd settlements/reedlake && python build.py`, then `python verify.py dist/reedlake.html --assert --views
  "Reed's Local — eye level,Opening" --out <scratch>/shots` (views are generated per building: check the exact view name
  the page prints). Look at the shots. Also run `python build.py --vendor-check` (you must not touch vendored files).
- Docs: add the def to `DESIGN.md` (the building table), `API.md` if you add helpers, `NOTES.md` (a dated round),
  `INDEX.md` is generated by `tools/make_index.py` — do NOT run it; give the planner the line.

## Part 2: the Reed Lake interiors set (`kits/interiors/sets/reedlake.js`, new)
- Read `kits/interiors/sets/README.md` fully (the item format, the frame, programmes, the residence rule), `API.md` as
  needed, and one existing set as a model (`kits/interiors/sets/locus.js`, which already has reed-mat rooms).
- One item per reed building def that has rooms: `rl_small_a`, `rl_small_b`, `rl_small_c`, `rl_large_a`, `rl_large_b`,
  `rl_longhouse`, `rl_warrior_hall`, `rl_shaman`, `rl_watchtower` (likely a `skip`: say why), `rl_weaver`,
  `rl_warehouse`, `rl_smithy`, `rl_farmhouse`, `rl_granary`, and the new `rl_tavern` (programme `tavern`: a bar or
  serving counter, seating for 40+, the cook-fire, store room). Variants: check each builder for `o.v` differences and
  add `#n` items where the rooms differ. `skip` (with the reason) for open structures: `rl_spirit_circle`, `rl_dock`,
  `rl_farm`, `rl_pen`, `rl_fishfarm`, the boats, the islands, `rl_village`.
  Read each BUILDER for its real body (mudhif length/span/rib height, hut walls, floor heights): do not guess from w x d.
- Furniture culture: `reedlake` (the catalog has `kits/catalog/krator-master-furniture-reedlake.js`). If a programme
  needs a piece the reedlake culture and its fallback chain lack (a tavern counter, a keg/jar rack, long benches, sleeping
  mats as beds), ADD it to that culture file in the catalog's own style (read `kits/catalog/README.md` "Furniture by
  culture" and `kits/furniture/SPEC.md` first; reed, mat, gourd, clay, eucalyptus pole; tag indoor/outdoor), then run
  `cd kits/catalog && python build.py && python verify.py dist/catalog.html --assert --page indoor` (slow; one page).
- Check: `cd kits/interiors && python build.py --sets-page reedlake` then
  `python verify.py dist/interiors-sets.reedlake.html --sets --assert --query set=reedlake` and a screenshot run with
  `--out <scratch>/shots --rooms`. Every residence passes the residence rule. Do NOT run the full `build.py` without
  `--sets-page` (another agent is writing a different set file at the same time; a full build is the planner's job).
- Add the row for your set to `kits/interiors/sets/README.md`'s table (that file is shared with two other agents
  adding one row each: make one small Edit adding your row only; re-read the file just before editing).
